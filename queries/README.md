# Финальная проверка сканера винных этикеток

В папке `queries/` находятся 100 контрольных фотографий: `eval_photo_001.webp`–`eval_photo_100.webp`. Список и идентификаторы находятся в `queries.tsv`.

Запустите свой сервис. Для runner нужны `bash`, `curl`, `jq`, `awk` и `shasum` или `sha256sum`. Сервис принимает POST-запрос с фотографией в multipart-поле `image` и возвращает `{"slug":"wine-slug"}`. Также поддерживается массив `[{"slug":"wine-slug"}]`: используется первый элемент.

Откройте терминал в папке распакованного пакета. Сначала проверьте целостность файлов:

```bash
shasum -a 256 -c checksums.sha256
# Linux: sha256sum -c checksums.sha256
```

Укажите адрес своего сервиса и запустите:

```bash
bash ./participant_test.sh \
  --images-dir ./queries \
  --manifest ./queries.tsv \
  --endpoint 'http://127.0.0.1:8080/v1/eval/predict' \
  --output ./predictions.jsonl
```

Для текущего API портала используйте endpoint `http://127.0.0.1:3003/v1/wines/search-by-photo?limit=1`.

Фотографии отправляются по порядку из manifest, строго по одной: запрос → полный ответ → запись результата → следующий запрос. Сервис должен возвращать ответ после завершения обработки изображения. Повторных попыток нет. Таймаут подключения — 5 секунд, всего запроса — 10 секунд.

После завершения появляется только `predictions.jsonl`. Каждая строка содержит ровно пять полей:

```json
{"query_id":"q-000001","image_path":"eval_photo_001.webp","image_sha256":"...","predicted_slug":"wine-slug","latency_ms":842}
```

Время измеряется runner от начала HTTP-запроса до получения полного ответа. При таймауте, ошибке HTTP или отсутствии корректного `slug` записывается `predicted_slug: null`; прогон продолжается. Результаты сначала записываются во временный файл и публикуются после завершения всех запросов.

Передайте `predictions.jsonl` организатору. Организатор сравнит ответы с закрытой таблицей и рассчитает `confidence`. Перед повторным запуском переименуйте предыдущий файл результата или задайте другой `--output`.
