# AI-сомелье

Детерминированный движок подбора вин по каталогу `app/sommelier/data/wines_integrated.csv` (2103 вина).
Признаки вина (сладость, тело, кислотность, танины, дуб, ароматы, блюда из описания) извлекаются только из
текста карточек; нет данных в базе → признак помечается как неизвестный, а не додумывается. Правила
сочетаемости, диалог с памятью, обратная связь и этические ограничения (guardrails: несовершеннолетние,
беременность, вождение и т.д.) не версионированы и подробно описаны в [`app/sommelier/README.md`](../app/sommelier/README.md)
(пять слоёв движка, ограничения, полнота разметки).

Роуты не версионируются (как `products`/`health`) — сомелье не часть search-пайплайна.

## Диалог: `POST /api/sommelier/ask`

```bash
curl -fsS -X POST http://127.0.0.1:8030/api/sommelier/ask \
  -H 'Content-Type: application/json' \
  -d '{"message": "стейк рибай, не люблю дуб"}'
```

Ответ:

```json
{
  "session_id": "3fae2a...c1",
  "kind": "recommendation",
  "text": "Разобрал блюдо: ...\n\n1. ...",
  "picks": [{"id": "slug-вина", "name": "...", "score": 87.5, "role": "Лучшее совпадение по правилам", "unknown": [], "reasons": [...]}],
  "types": [{"cat": "Красное", "sweet": "сухое", "sparkling": false, "verdict": "подходит"}],
  "pool": 214,
  "context": {"dish": {...}, "colors": ["Красное"], "avoid_oak": true, ...}
}
```

`session_id` в первом ответе нужно передавать в последующих сообщениях того же диалога — движок помнит блюдо,
предпочтения и исключённые (после «не понравилось») вина внутри сессии. Сессии живут в памяти процесса API
(без БД) с TTL и лимитом `SOMMELIER_SESSION_TTL_SECONDS` / `SOMMELIER_MAX_SESSIONS`; при перезапуске API все
диалоги начинаются заново — это демо-уровень персистентности, не для долговременного хранения переписки.

`kind` в ответе: `recommendation` (подбор), `clarify` (нужно уточнение), `guardrail` (отказ — несовершеннолетний,
вождение и т.п., см. `text`), `comparison`/`profile` (различия сортов/типов по статистике каталога), `wine_info`
(справка по вину), `feedback` (оценка принята), `not_found`.

## Новый диалог: `POST /api/sommelier/reset`

```bash
curl -fsS -X POST http://127.0.0.1:8030/api/sommelier/reset \
  -H 'Content-Type: application/json' -d '{"session_id": "3fae2a...c1"}'
```

Отвечает `{"ok": true}` или `404`, если `session_id` не известен (например, TTL истёк).

## Точка интеграции с распознаванием этикеток: `GET /api/sommelier/wine/{slug}`

`slug` — идентификатор товара, который вернул `/api/v1/search` (`product.slug` совпадает со slug из
`wines_integrated.csv`, если товар из этого каталога). Разовый запрос без диалоговой сессии.

```bash
curl -fsS "http://127.0.0.1:8030/api/sommelier/wine/fanagoriya-100-ottenkov-krasnogo-kaberne-kaberne-sovinon-krasnoe-suhoe-135"
curl -fsS "http://127.0.0.1:8030/api/sommelier/wine/<slug>?dish=%D1%81%D1%82%D0%B5%D0%B9%D0%BA%20%D1%80%D0%B8%D0%B1%D0%B0%D0%B9"
```

Без `dish` — справка по вину из базы (стиль, сладость, ароматы, цитата из описания). С `dish` (текст блюда,
как во free-text запросе) — та же справка плюс оценка сочетания по правилам движка. Неизвестный `slug` даёт
`{"kind": "not_found", ...}`, а не ошибку.

## Альтернативы к распознанному вину: `GET /api/sommelier/wine/{slug}/alternatives`

Похожие по стилю вина каталога (`limit` — от 1 до 20, по умолчанию 5). Жёсткие условия: тот же цвет и
игристость, сладость отличается не больше чем на ступень. Дальше скоринг по сорту, типу, телу, танинам,
кислотности, общим ароматам, региону и дубу; не больше двух вин одной винодельни, одноимённые вина не
повторяются. Каждый довод взят из полей карточки, картинка — этикетка из каталога распознавания (если вино там есть).

```bash
curl -fsS "http://127.0.0.1:8030/api/sommelier/wine/belbek-roze-sira-rozovoe-suhoe-125/alternatives?limit=3"
```

```json
{"kind": "alternatives", "id": "belbek-roze-sira-rozovoe-suhoe-125", "items": [
  {"id": "…", "name": "Розе. Авторское вино", "winery": "Массандра", "facts": "розовое, сухое · сорт: Сира",
   "score": 0.84, "reasons": ["тот же сорт: Сира", "тот же тип: розовое сухое", "общие ноты: красные ягоды"],
   "image_url": "/api/media/products/…/label.webp"}
]}
```

Сканер `/search-cascade` показывает справку и альтернативы под распознанным вином; при ответе «нет в каталоге»
вместо них — поле вопроса к сомелье (`POST /api/sommelier/ask`).

## Готовность

`GET /api/ready` включает информационное поле `sommelier` (каталог собрался при старте API). Оно не влияет на
итоговый `ready` (сомелье — вспомогательная функция, а не блокирующая зависимость поиска по этикеткам).

## Конфигурация

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SOMMELIER_MAX_SESSIONS` | 500 | верхний предел одновременных диалоговых сессий в памяти |
| `SOMMELIER_SESSION_TTL_SECONDS` | 3600 | сессия без обращений дольше этого времени вытесняется |

Источник данных — `app/sommelier/data/wines_integrated.csv`, путь можно переопределить `SOMMELIER_CSV_PATH`
(обычно не требуется: файл поставляется вместе с кодом). Каталог собирается из CSV один раз при старте API
(доли секунды на ~2000 строк) и не кэшируется на диск — `app/` в проде смонтирован read-only. Отзывы
(«не понравилось» / «понравилось», см. `app/sommelier/README.md`, слой 5) пишутся в `media/sommelier/feedback.jsonl`
(writable-том) и накапливаются как задел для будущей калибровки весов правил — сейчас ничего с ними
автоматически не делается.

## Необязательный LLM-слой

`app/sommelier/llm.py` — переписывает шаблонный ответ движка живым языком через Anthropic API и откатывается
к шаблону при любом нарушении проверок (упомянуты не те вина, побуждающая лексика, цены). В HTTP API он **не
подключён** — `POST /api/sommelier/ask` всегда возвращает шаблонный `text`. Требует `pip install anthropic` и
`ANTHROPIC_API_KEY`; в этой среде против живого API не запускался (см. ограничения в `app/sommelier/README.md`).
