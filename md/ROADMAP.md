# Дорожная карта развития проекта (ROADMAP) — LCT2026

Документ фиксирует стратегические инициативы, архитектурные улучшения и планы по интеграции для победы в соревновании и внедрения у заказчика.

---

## Приоритет 1: Включение `cylinder_warp` и `shadow` в генерацию эталонных векторов (116 эмбеддингов)

### Проблема
- При импорте товаров в базу `ProductIngestionService` строит облако из 116 векторов (1 оригинал + 23 аугментации × 5 вариантов).
- Новые функции аугментации — **`cylinder_warp` (цилиндрический изгиб)** и **`shadow` (направленная тень)** — используются сейчас только при тестировании поиска на странице `/twins`, но отсутствуют в базе каталога.
- В результате база не знает, как выглядит этикетка при изгибе по бутылке, что увеличивает косинусное расстояние при поиске реальных фото.

### Задачи
1. Заменить 2 наименее эффективные аугментации в списке `BASE_CATALOG_AUG_NAMES` на `cylinder_warp` и `shadow`.
2. Сохранить канонический размер облака: ровно **116 векторов на товар** (не раздувая базу данных).
3. Обеспечить пересчёт эмбеддингов для каталога при необходимости.

## Приоритет 2: Выпрямление этикеток через маску сегментации YOLO (Dewarping / Rectification)

### Концепция
- Использовать рабочую модель сегментации `models/yolo_seg.pt`.
- Вместо простого прямоугольного BBox-кропа извлекать точный полигон этикетки.
- Находить 4 опорные вершины (углы) этикетки в кадре и через проективное преобразование (`cv2.getPerspectiveTransform` + `cv2.warpPerspective`) **расправлять перспективную трапецию в идеальный фронтальный квадрат 256×256**.
- Применять этот процесс симметрично:
  - при добавлении товара в каталог;
  - при поиске по фото с камеры.

### Задачи
1. Реализовать модуль деварпинга `app/services/rectification.py`.
2. Добавить визуальный переключатель выпрямления на страницу `/detect-test` для отладки на реальных фото бутылок.
3. Оценить влияние выпрямления на число inliers в SIFT и устойчивость DINOv2.

## Приоритет 3: Баш-скрипт регламентного тестирования заказчика

### Концепция

- Скрипт принимает тестовый датасет, замеряет скорость (Latency), точность (Top-1, Top-5), потребление памяти GPU и формирует отчёт в требуемом формате (`submission.csv` / `results.json`).

### Задачи
1. Дождаться загрузки эталонного скрипта и спецификации заказчика в репозиторий.
2. Провести аудит входных/выходных контрактов, аргументов CLI и окружения.
3. Настроить запуск тестов внутри Docker-контейнера `api` одной командой:
   ```bash
   docker compose exec api bash scripts/eval_submission.sh
   ```

## Приоритет 4: Экспортный мобильный сканер с интеграцией CMS заказчика

### Архитектура решения
```text
[ Камера смартфона ] 
        │
        ▼ (POST фото)
[ LCT2026 AI Backend ]  ───►  Возвращает JSON { "slug": "avtohtonnoe-vino-...", "confidence": 0.98 }
        │
        ▼ (GET slug)
[ API CMS vino-svoe.ru ] ───► Возвращает карточку товара (цена, остатки, магазины)
        │
        ▼
[ Виджет сканера в CMS ] ───► Пользователь видит карточку найденного вина
```

### Задачи
1. **Инспекция API сайта заказчика (`vino-svoe.ru`):**
   - Исследовать Strapi REST API эндпоинты (`/api/wines?filters[slug][$eq]=...`).
   - Определить структуру возвращаемых данных карточки вина.
2. **Разработка автономной мобильной страницы сканера:**
   - Адаптивный мобильный интерфейс (PWA-ready) с прямым доступом к видеопотоку камеры (`getUserMedia`).
   - Автоматический захват кадра с видоискателем (прицелом на этикетку).
   - Асинхронный вызов нашего backend API `/api/v1/search` $\to$ получение `slug`.
   - Запрос данных карточки вина из CMS заказчика и вывод модальной карточки с кнопкой «Купить / Подробнее».
3. **Упаковка:** подготовка в виде легковесного автономного JS/HTML-модуля для интеграции в CMS заказчика.

## Приоритет 5: Доработка реранкера SIFT (Защитный шлюз доверия)

### Задачи
1. Внедрить **Gated Re-ranking**: SIFT имеет право менять победителя только при уверенном количестве совпадений ($\ge 15\text{--}20$ inliers).
2. При низком качестве SIFT-соответствий (сильные искажения) сохранять лидерство Top-1 от DINOv2.
3. Заменить классический RANSAC на `cv2.USAC_MAGSAC` с увеличенным порогом ошибки репроекции (до 8.0 px) для устойчивости к цилиндрическому изгибу.
