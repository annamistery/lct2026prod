# Инструкция по проверке сканера (participant_test)

## 0. Восстановление данных каталога «из коробки» (при первом запуске)

Если проект развёрнут на чистом сервере, восстановите готовую базу и эталонные кропы одной командой:

```bash
chmod +x scripts/*.sh
./scripts/restore_production_data.sh
```

Скрипт автоматически:
- загрузит каталог из `data/dump_products.sql.gz` — 2017 вин;
- создаст расширение pgvector и таблицы векторов по схеме `data/schema_embeddings.sql`;
- загрузит векторы v4 (SigLIP 2) и v1 (DINOv2) — по 233 972 строки из `data/dump_embeddings_v4.sql.gz` и `data/dump_embeddings_v1.sql.gz` (несколько минут);
- распакует эталонные кропы этикеток в `media/`;
- запустит API и проверит его готовность. При первом запуске собирается Docker-образ — 10–20 минут.

Повторный запуск скрипта заново загружает каталог и векторы (старые векторы удаляются).

Проверка готовности:

```bash
curl http://127.0.0.1:8030/api/ready
# {"ready":true,"database":true,"models":true,"sommelier":true}
```

## 1. Куда положить тестовые данные

В корневую папку проекта:
- **`queries/`** — папка с контрольными изображениями этикеток/бутылок.
- **`queries.tsv`** — файл со списком контрольных изображений (формат: `query_id<TAB>image_path`).

Пример структуры в корне:
```text
~/lct2026prod/
├── queries/
│   ├── 019c68d0.jpg
│   └── 019c68d1.jpg
└── queries.tsv
```

Готовые контрольные наборы с правильными ответами (`mapping.json`) лежат в `tmp/1` и `tmp/2`.

## 2. Запуск проверки

Убедитесь, что Docker-контейнер `api` запущен (`docker compose ps`), и выполните команду из корня проекта:

```bash
chmod +x md/participant_test.sh
./md/participant_test.sh --images-dir ./queries --manifest ./queries.tsv \
    --endpoint http://127.0.0.1:8030/api/cascade/predict --output predictions.jsonl
```

Скрипт отправляет каждое фото на каскадный распознаватель `POST /api/cascade/predict` (DINOv2 + SigLIP 2, выбор этикетки по центру кадра), получает Top-1 `slug` и замеряет `latency_ms`. `--endpoint` можно не указывать: этот адрес используется по умолчанию.

Проверка на готовом наборе:

```bash
./md/participant_test.sh --images-dir tmp/1/queries --manifest tmp/1/queries.tsv --output predictions_tmp1.jsonl
```

Для скрипта нужны `curl` и `jq` (на Windows: `winget install jqlang.jq`, команды выполнять в Git Bash).

> Адрес `/api/v1/eval/predict` — прежний распознаватель v1 (только DINOv2). Он оставлен для сравнения и заметно менее точен, для проверки его не используйте.

---

## 3. Где забрать результат

Результат формируется в файле, указанном в `--output` (по умолчанию `predictions.jsonl` в корне проекта).

Каждая строка содержит JSON-результат проверки одного фото:
```json
{"query_id":"q-000001","image_path":"019c68d0.jpg","image_sha256":"8d9c821e...","predicted_slug":"avtohtonnoe-vino-kryma-beloe-suhoe","latency_ms":240}
```

Если вина нет в каталоге, `predicted_slug` равен `null`.

Файл `predictions.jsonl` передаётся организаторам соревнования для подсчёта финального скора.

> **Примечание:** если файл уже существует от предыдущего запуска, скрипт остановится с ошибкой. Перед новым тестом удалите его: `rm -f predictions.jsonl`.
