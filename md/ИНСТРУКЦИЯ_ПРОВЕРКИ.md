# Инструкция по проверке сканера (participant_test)

## 0. Восстановление данных каталога «из коробки» (при первом запуске)

Если проект развёрнут на чистом сервере, восстановите готовую базу и эталонные кропы одной командой (займёт всего ~30–40 секунд):

```bash
chmod +x scripts/restore_production_data.sh
./scripts/restore_production_data.sh
```

Скрипт автоматически:
- загрузит дамп PostgreSQL со всеми 1932 товарами и 224,000 эмбеддингами pgvector из `data/catalog_dump.sql.gz`;
- распакует эталонные кропы этикеток в `media/products/`;
- перезапустит сервис и проверит готовность API.

---

## 1. Куда положить тестовые данные

В корневую папку проекта:
- **`queries/`** — папка с контрольными изображениями этикеток/бутылок.
- **`queries.tsv`** — файл со списком контрольных изображений (формат: `query_id<TAB>image_path`).

Пример структуры в корне:
```text
~/lct2026prod/
├── queries/
│   ├── 019c68d0.jpg
│   └── 019c68d1.jpg
└── queries.tsv
```

---

## 2. Запуск проверки

Убедитесь, что Docker-контейнер `api` запущен (`docker compose ps`), и выполните команду из корня проекта:

```bash
chmod +x md/participant_test.sh
./md/participant_test.sh --images-dir ./queries --manifest ./queries.tsv
```

Скрипт автоматически отправляет запросы на наш бэкенд (`http://127.0.0.1:8030/api/v1/eval/predict`), получает Top-1 `slug` и замеряет `latency_ms`.

---

## 3. Где забрать результат

Результат формируется в корне проекта в файле:
- **`predictions.jsonl`**

Каждая строка содержит JSON-результат проверки одного фото:
```json
{"query_id":"q-000001","image_path":"019c68d0.jpg","image_sha256":"8d9c821e...","predicted_slug":"avtohtonnoe-vino-kryma-beloe-suhoe","latency_ms":240}
```

Файл `predictions.jsonl` передаётся организаторам соревнования для подсчёта финального скора.

> **Примечание:** если файл `predictions.jsonl` уже существует от предыдущего запуска, перед новым тестом удалите его: `rm -f predictions.jsonl`.
