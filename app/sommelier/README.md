# AI-сомелье по каталогу российских вин

Гибрид «детерминированный движок + LLM для речи». Выбор вина и все факты — из `data/wines_integrated.csv`;
LLM (необязательно, `llm.py`) только формулирует ответ и проверяется на соответствие выдаче движка.

Вендорировано как пакет `app.sommelier` внутри lct2026prod (изначально — отдельный прототип). HTTP-точка входа —
`/api/sommelier/*`, описана в [`docs/SOMMELIER.md`](../../docs/SOMMELIER.md). Для ручной проверки без HTTP:

```bash
python scripts/sommelier_cli.py                          # диалог в консоли
python scripts/sommelier_cli.py "стейк рибай, не люблю дуб"
python -m pytest tests/test_sommelier.py -q
```

Зависимость движка — только `pandas`. Для необязательного LLM-слоя: `pip install anthropic` и `ANTHROPIC_API_KEY`
(в HTTP API этот слой не подключён — см. `docs/SOMMELIER.md`).

## Пять слоёв
| Слой | Файл | Что делает |
|---|---|---|
| 1. Контекст | `context.py`, `dishes.py` | текст → блюдо на осях (интенсивность, жир, кислота, сладость, соль, острота), цвет, сладость, сорта «люблю/не люблю», дуб, повод, уровень гостя, бюджет |
| 2. База знаний | `features.py`, `catalog.py` | из описания/названия/slug извлекаются тело, кислотность, танины, сладость, игристое, дуб, выдержка, ароматы, «блюда из карточки»; у каждого признака — цитата-доказательство или `None` |
| 3. Движок | `engine.py` | жёсткие фильтры → скоринг 8 правил → диверсификация (лучший / классика / редкий сорт) → уместность типов вина |
| 4. Объяснение | `explain.py`, `llm.py`, `SYSTEM_PROMPT.md` | причины из вкладов правил, цитаты из базы, три уровня подачи; LLM опционально |
| 5. Обратная связь | `sommelier.py` | «не понравилось 2» исключает вино из сессии, оценки пишутся в `feedback_log` (по умолчанию `media/sommelier/feedback.jsonl` в проде — см. `docs/SOMMELIER.md`; для калибровки весов `engine.W`) |

Рекомендации по логике сомелье (методика из ТЗ): вес блюда ≈ тело вина; кислотность режет жир; сладость вина ≥ сладости блюда;
танины дружат с белком/жиром и конфликтуют с солью/остротой; контраст/дополнение по аромату; региональный принцип.
Итоговый балл нормируется по правилам, применимым к запросу: **нет данных о вине → нет баллов** (вино с подтверждёнными признаками
обходит вино, о котором база молчит).

## Три требования ТЗ
- **Строго по базе.** Признаки только из текста карточек; нет данных → «в базе не указано». Два исключения, оба помечены в ответе:
  танины красного вина без упоминания оцениваются медианой по красным каталога (вклад вдвое слабее); разбор блюда (словарь
  `dishes.py`) — это интерпретация запроса, а не факт о вине.
- **Не уговаривает.** `guardrails.py`: отказ при несовершеннолетии, беременности, вождении, лекарствах/зависимости, «напиться»,
  «сколько выпить»; отказ гостя от вина принимается без уговоров; список запрещённых побуждающих оборотов проверяется в каждом ответе;
  в конце — нейтральная пометка, что вино не обязательно.
- **Различия и уместность.** «Чем отличается Мерло от Каберне» и «расскажи про Саперави» считаются по статистике описаний каталога
  (с числом вин в выборке); к любому блюду показывается уместность типов вина (сухое/сладкое, цвет, игристое) с причиной.

## Интеграция с распознаванием этикеток
`Sommelier().about_wine(slug_или_название, dish=None)` — принимает `id` (slug) распознанного вина или строку с названием,
возвращает карточку, блюда из описания и, если передан разбор блюда, оценку по правилам. В проде это `GET /api/sommelier/wine/{slug}`
(см. `docs/SOMMELIER.md`) — вызывается со slug товара, найденного `/api/v1/search`.

## Полнота разметки (2103 вина)
сладкость 78% · тело (косвенно, по словам) 77% · кислотность 47% · танины 24% · выдержка 7% · подача 1% · крепость 0%.
Где данных нет, движок это показывает и не додумывает.

## Ограничения (честно)
- **Нет цен и наличия** — бюджет фиксируется, но не применяется; в ответе об этом сказано.
- **Тело вина — косвенная оценка** по словам («плотный», «лёгкий»), с поправкой на танины и выдержку. Это главный кандидат на ручную разметку.
- Веса правил заданы вручную и не калибровались на реальных удачных парах; нужна оценка сомелье-эксперта.
- В базе 66 вин без страницы на сайте (без ссылки/картинки), сорта частично «грязные» (очищено в `catalog.clean_grapes`: «Молдова» и «Красные сорта винограда» — не сорта).
- LLM-слой (`llm.py`) написан, компилируется, но **не запускался против API** (нет ключа/пакета в этой среде), и не подключён в HTTP API.
- Русская морфология — регулярные выражения по основам слов; редкие формулировки могут не распознаться (тогда движок спросит уточнение или пропустит признак).
- Нет коллаборативной фильтрации (холодный старт): накопленные записи обратной связи — задел на следующий этап.
- Диалоговые сессии HTTP API живут только в памяти процесса (без БД) с TTL/лимитом — не рассчитаны на долговременное хранение переписки.
